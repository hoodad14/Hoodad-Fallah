# گزارش کنترل نهایی فرانت‌اند ArenaPass

تاریخ کنترل: 2026-08-04

## دامنه کنترل

فرانت‌اند با نیازمندی‌های پروژه، مسیرهای ثبت‌شده در بک‌اند و قرارداد `openapi.json` تطبیق داده شد. ساختار پوشه‌ای پروژه تغییر نکرده و همه فایل‌ها همچنان در همان پوشه تخت قرار دارند.

## کنترل‌های انجام‌شده

| وجود عناصر لازم برای Drawer فیلتر، Banner اتصال و تنظیمات API | موفق |

## اصلاحات اصلی فرانت‌اند

- حذف Base URL ثابت و تشخیص خودکار `/api/v1` در اجرای Nginx/Docker یا پورت ۸۰۰۰ در اجرای دستی
- بررسی Readiness واقعی شامل API، PostgreSQL و Redis به‌جای Health ساده
- Auto-discovery آدرس API و امکان Reset واقعی تنظیم اتصال
- جلوگیری از بازنویسی نتایج جستجوی جدید توسط پاسخ‌های قدیمی
- تکمیل رفتار فیلتر تاریخ، مرتب‌سازی، صندلی شماره‌دار و فیلترهای URL در حالت Preview
- اصلاح Drawer فیلتر موبایل با دکمه بستن، Backdrop، قفل Scroll و پشتیبانی Escape
- اصلاح لینک‌های راهنما برای سازگاری با Router تک‌صفحه‌ای
- محدودکردن تب‌های خرید و کیف پول به نقش تماشاگر
- پاک‌سازی نشست ناقص و الزام وجود هم‌زمان User و Access Token
- حذف تزریق Inline برای تصویر پروفایل و افزودن Fallback امن DOM
- نمایش `Retry-After` و شناسه پیگیری خطاهای API
- همگام‌سازی فرم مدیریت بلیط با قواعد بک‌اند: ظرفیت ۱ برای صندلی شماره‌دار و الزام ردیف/صندلی
- حفظ امکانات انتخاب‌شده در ویرایش بلیط‌های پنل پشتیبانی
- اصلاح پاک‌کردن فیلتر شهر و بازگرداندن کامل فهرست ورزشگاه‌ها

## اصلاحات اتصال و استقرار

- افزودن سرویس `frontend` مبتنی بر Nginx به Docker Compose
- افزودن Reverse Proxy برای مسیر `/api/` و استفاده از اتصال داخلی `backend:8000`
- حذف Syntax جدید و ناسازگار `env_file.required` از Compose
- امکان اجرای Compose بدون `.env` با Defaults محلی، در کنار `setup_env.py` برای ساخت فایل شخصی
- افزودن Healthcheck فرانت‌اند و انتظار برای سالم‌شدن Readiness بک‌اند
- افزودن Headerهای امنیتی و CSP در Nginx
- گسترش CORS برای پورت‌های رایج توسعه ۳۰۰۰، ۵۵۰۰ و ۸۰۸۰
- افزودن `amenity_ids` به خروجی مدیریت بلیط برای جلوگیری از پاک‌شدن ناخواسته امکانات هنگام ویرایش

## اصلاحات نسخه 1.6.0

- افزودن کلید زبان کنار دکمه پوسته با نمایش زبان فعلی (`FA` یا `EN`)
- اتصال دوباره `i18n.js` پیش از `app.js` برای ترجمه مطمئن رابط ثابت و محتوای پویا
- ذخیره زبان در `localStorage` و بازیابی خودکار آن پس از Refresh
- تغییر هم‌زمان `lang`، `dir`، عنوان صفحه، Meta Description و فونت بین فارسی و انگلیسی
- اعمال اصلاحات LTR برای منوی کاربر، فرم رمز، Dialogها و کارت‌های گفتگوی پشتیبانی
- مستثناکردن متن واقعی پیام‌های کاربران از ترجمه با `data-i18n-ignore`
- حفظ کشش فنری Transform-only دکمه چت و جلوگیری از پرش Scroll هنگام بستن

## بررسی مرورگری نسخه 1.6.0

- تغییر `FA → EN → FA` با یک کلیک و بازیابی کامل متن فارسی بررسی شد.
- منوی اصلی، تیتر Hero، دکمه ورود، عنوان مرورگر و محتوای پویای افزوده‌شده در حالت انگلیسی بررسی شدند.
- جهت سند در حالت فارسی `rtl` و در حالت انگلیسی `ltr` بود.
- زبان انتخاب‌شده برای بارگذاری بعدی در `localStorage` ذخیره می‌شود.
- موشن اسکرول دکمه چت محدود و Transform-only باقی مانده و Scroll صفحه هنگام بستن حفظ می‌شود.

## محدودیت کنترل

اتصال‌ها و قراردادها از نظر کد، Syntax، مسیرها، Compose و تست‌های مستقل بررسی شده‌اند. تأیید نهایی تراکنش‌های رزرو، پرداخت، Redis و PostgreSQL نیازمند اجرای `docker compose up --build -d` در محیط دارای Docker است. پس از اجرا، مسیر `http://127.0.0.1:8080/api/v1/ready` باید وضعیت آماده سرویس‌ها را برگرداند.

## Database bootstrap hotfix

The Docker startup log exposed a seed-order defect: reservation identity values were generated in an unspecified join order while later seed rows referenced fixed reservation IDs. Reservation IDs are now inserted explicitly and the database healthcheck waits for a final bootstrap marker.
