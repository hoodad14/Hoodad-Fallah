# راهنمای فرانت‌اند ArenaPass

فرانت‌اند این بسته با **HTML، CSS و JavaScript خالص** پیاده‌سازی شده است؛ هیچ فریم‌ورک، پکیج npm، CDN یا وابستگی زمان اجرا ندارد. سه فایل اصلی آن مستقیماً در همین پوشه تخت قرار گرفته‌اند:

- `index.html` - ساختار کامل رابط کاربری تک‌صفحه‌ای
- `styles.css` - طراحی RTL، واکنش‌گرا، حالت روشن/تیره و تمام مؤلفه‌های بصری
- `app.js` - مسیریابی، مدیریت وضعیت، احراز هویت، اتصال به API، فرم‌ها و پنل‌ها

## امکانات پیاده‌سازی‌شده

### بخش عمومی

- صفحه اصلی حرفه‌ای با معرفی سامانه، دسته‌بندی ورزش‌ها، مسابقات نزدیک و جستجوی سریع
- کاتالوگ بلیط با فیلترهای نوع ورزش، تیم/عبارت، شهر، ورزشگاه، رده، تاریخ، قیمت، ظرفیت و صندلی شماره‌دار
- مرتب‌سازی براساس زمان، قیمت، تقاضا و موجودی
- صفحه‌بندی، نمایش فیلترهای فعال، وضعیت خالی، Skeleton Loading و مدیریت خطا
- نمایش جزئیات کامل بلیط، امکانات، محل، رده و محاسبه مبلغ براساس تعداد

### احراز هویت

- ورود با رمز عبور
- درخواست، نمایش فرم کد شش‌رقمی، ارسال مجدد و تأیید OTP
- ثبت‌نام کاربر جدید
- نگه‌داری انتخابی نشست در Local Storage یا Session Storage
- Refresh خودکار JWT در پاسخ 401 و خروج امن
- حساب‌های نمونه آماده برای نمایش در محیط Local

### پنل تماشاگر

- نمای کلی حساب، کیف پول، رزروهای فعال و بلیط‌های آینده
- تاریخچه رزروها با جزئیات و شمارش معکوس انقضا
- پرداخت رزرو با روش‌های اعلام‌شده از API
- مشاهده بلیط‌های صادرشده و اطلاعات QR برگشتی سرور
- دریافت برآورد جریمه، ثبت درخواست کنسلی و استرداد
- ثبت درخواست تغییر جایگاه
- مشاهده تراکنش‌ها و افزایش موجودی Local در صورت فعال‌بودن بک‌اند
- ثبت و مشاهده گزارش مشکلات
- ویرایش پروفایل، تغییر رمز با OTP و تغییر ایمیل/شماره تماس با تأیید دومرحله‌ای

### گفتگوی پشتیبانی

- دکمه دایره‌ای شناور با حرکت نرم همراه اسکرول؛ دکمه از `position: absolute` و همگام‌سازی JavaScript استفاده می‌کند و Fixed نیست.
- گفتگوی خصوصی هر تماشاگر با پیام‌های خوانده‌نشده و Polling سبک HTTP.
- تب «گفتگوها» در پنل پشتیبان برای مشاهده صف، پاسخ، بستن و بازگشایی مکالمه.
- در موبایل پنل چت به‌صورت واکنش‌گرا و تمام‌عرض‌تر نمایش داده می‌شود.

### پنل پشتیبان

- داشبورد شاخص‌های عملیاتی
- جستجو و بررسی رزروها
- تأیید، اصلاح وضعیت یا لغو مدیریتی رزرو
- اصلاح امن جایگاه از مسیر API پشتیبان
- غیرفعال‌سازی کاربر
- بررسی درخواست‌های کنسلی و تغییر صندلی
- رسیدگی به گزارش‌های کاربران
- مشاهده پرداخت‌های مشکوک
- ایجاد، ویرایش و غیرفعال‌سازی ردیف بلیط

### کیفیت رابط کاربری

- رابط کامل دو‌زبانه فارسی/انگلیسی با تغییر خودکار RTL/LTR
- واکنش‌گرا برای دسکتاپ، تبلت و موبایل
- منوی موبایل و Drawer فیلترها
- حالت روشن و تیره با ذخیره انتخاب کاربر
- کلید `FA / EN` کنار دکمه پوسته با ذخیره زبان انتخاب‌شده و ترجمه متن‌های ثابت و پویا
- Dialogهای استاندارد، اعلان Toast، Loading سراسری و پیام‌های خطای قابل‌پیگیری
- Escape کردن داده‌های برگشتی سرور پیش از درج در HTML
- حالت Preview آفلاین برای نمایش رابط حتی پیش از بالا آمدن سرور؛ عملیات واقعی در این حالت غیرفعال یا به ورود/سرور هدایت می‌شوند

## اجرای کامل پروژه

### ۱. اجرای یکپارچه فرانت‌اند، بک‌اند، دیتابیس و Redis

در همین پوشه اجرا کنید:

```bash
python setup_env.py
docker compose up --build -d
```

ساخت `.env` برای شخصی‌سازی توصیه می‌شود، اما Compose با مقادیر نمایشیِ محلی پیش‌فرض نیز اجرا می‌شود؛ این مقادیر برای Production مناسب نیستند.

در صورت نیاز به Elasticsearch:

```bash
docker compose --profile search up --build -d
```

آدرس‌های پیش‌فرض:

```text
وب‌سایت:       http://127.0.0.1:8080 (یا FRONTEND_HOST_PORT)
API از Nginx:  http://127.0.0.1:8080/api/v1
صندوق OTP:     http://127.0.0.1:8080/mailpit/  (همان پورت فرانت‌اند)
API مستقیم:    http://127.0.0.1:8000/api/v1
```

سرویس Nginx فایل‌های `index.html`، `styles.css` و `app.js` را ارائه و تمام درخواست‌های `/api/` را به سرویس `backend` پروکسی می‌کند. فرانت‌اند در این حالت Base URL هم‌دامنه `/api/v1` را خودکار انتخاب می‌کند.

### ۲. اجرای دستی فرانت‌اند در حالت توسعه

در صورت نیاز به اجرای جداگانه رابط:

```bash
python -m http.server 3000
```

سپس `http://127.0.0.1:3000` را باز کنید. برنامه به‌طور خودکار API روی همان میزبان و پورت ۸۰۰۰ را پیدا می‌کند. بازکردن مستقیم `index.html` فقط برای پیش‌نمایش آفلاین مناسب است.

## تغییر نشانی API

در رابط کاربری، دکمه تنظیمات کنار تغییر پوسته را باز کنید و Base URL جدید را وارد کنید. مقدار در مرورگر ذخیره می‌شود. مقدار پیش‌فرض براساس شیوه اجرا خودکار تعیین می‌شود:

```text
Docker/Nginx: /api/v1
اجرای دستی:  http://127.0.0.1:8000/api/v1
```

در صورت تغییر دامنه یا پورت فرانت‌اند، مقدار `CORS_ALLOWED_ORIGINS` در `.env` بک‌اند نیز باید همان Origin را شامل شود.

## قرارداد اتصال

تمام مسیرهای فراخوانی‌شده در `app.js` با مسیرهای موجود در `openapi.json` تطبیق داده شده‌اند. پاسخ‌های استاندارد زیر پشتیبانی می‌شوند:

```json
{
  "success": true,
  "data": {},
  "meta": {}
}
```

و خطاها:

```json
{
  "success": false,
  "error": {
    "code": "...",
    "message": "...",
    "details": {},
    "request_id": "..."
  }
}
```

- هیچ پوشه فرعی برای فرانت‌اند ساخته نشده است.
- ساختار تخت پروژه حفظ شده و اصلاحات اتصال، CORS، تنظیمات Docker و داده‌های فرم مدیریت بلیط در همان فایل‌های موجود اعمال شده‌اند.
- تصاویر Preview صرفاً برای مشاهده سریع کیفیت رابط هستند و در اجرای برنامه نقشی ندارند.
- انجام تراکنش واقعی، رزرو و تغییر داده به بالا بودن سرویس‌های بک‌اند وابسته است.


## تست ورود و ثبت‌نام

- فرم OTP پس از پاسخ موفق `POST /auth/otp/request` از حالت مخفی خارج می‌شود و فیلد `autocomplete="one-time-code"` دارد.
- ثبت‌نام در دو مرحله انجام می‌شود: شروع ثبت‌نام، دریافت OTP، سپس `POST /auth/signup/verify`. تا قبل از تأیید OTP هیچ User فعالی ساخته نمی‌شود.
- در Docker، ایمیل پس از ذخیره قطعی در Mailpit موفق اعلام می‌شود؛ کد را از مسیر `/mailpit/` همان Origin سایت بردارید.
- فرانت‌اند همیشه API هم‌دامنه `/api/v1` را ترجیح می‌دهد، بنابراین تغییر پورت میزبان از 8080 به 8081 باعث خرابی CORS یا ورود نمی‌شود.
- راهنمای مرحله‌به‌مرحله در `AUTHENTICATION_GUIDE.md` است.


## Mailpit UI fallback

رابط Mailpit فقط از مسیر هم‌مبدأ `/mailpit/` روی همان آدرس فرانت‌اند در دسترس است؛ برای نمونه `http://localhost:8080/mailpit/`. این روش از تداخل پورت و بازشدن نمونه اشتباه Mailpit جلوگیری می‌کند.

### دکمه زبان و دکمه پایدار پشتیبانی (Frontend v1.6.0)

کلید زبان کنار دکمه پوسته قرار دارد و زبان فعلی را با `FA` یا `EN` نشان می‌دهد. کلیک روی آن رابط را بین فارسی/RTL و انگلیسی/LTR جابه‌جا می‌کند؛ انتخاب زبان نیز پس از Refresh حفظ می‌شود. دکمه چت روی یک Dock ثابت قرار دارد، اما هنگام اسکرول کشش فنری محسوس‌تری روی خود دکمه اجرا می‌شود. این افکت فقط با `transform` انجام می‌شود و مقدار `top` یا Scroll صفحه را تغییر نمی‌دهد؛ بنابراین بستن پنجره چت باعث پرش صفحه نمی‌شود.

برای تغییر شدت افکت، در `app.js` عبارت `SUPPORT_CHAT_MOTION_CONFIG` را جستجو کنید. افزایش `MAX_OFFSET` باعث جابه‌جایی بیشتر، افزایش `IMPULSE_FACTOR` باعث واکنش قوی‌تر به Scroll، افزایش `DAMPING` باعث برگشت آهسته‌تر و افزایش `MAX_STRETCH` باعث کشیدگی بیشتر شکل دکمه می‌شود.
